# M0.1 corrective release — gating and rollback runbook

## Baseline and incident
- Baseline `main`: `3e7f8e13c0f404f28571ed1965c0e21aaf984244`.
- On 2026-11-06 (SGT), deployment workflow 42097067760 completed successfully while separately configured browser E2E workflow 42097067724 failed 2 WebKit tests (15 passed). This was a release-gate orchestration defect.
- Main was reported unprotected and no repository rulesets were returned during baseline inspection.
- GitHub Pages deploy-job success alone is **not** public site smoke testing or product owner acceptance.

## Mandatory pre-merge validation
1. Review PR diff and privacy/security impact. Never approve changes on the basis of green compilation alone.
2. Confirm the **same candidate SHA** passed `verify`, `browser-tests` and `codeql-gate` in **Secure CI and GitHub Pages deployment**; check the independent scheduled CodeQL and browser workflows.
3. `verify` must pass lockfile-based `npm ci`, `npm audit --audit-level=high`, strict TypeScript, unit tests, build, CycloneDX SBOM and SHA-256 manifest.
4. `browser-tests` must pass all configured Chromium, desktop WebKit and mobile WebKit scenarios without skipping failures. Examine trace artifacts on any failure; reruns are supporting evidence, not proof a flaky test is resolved.
5. `codeql-gate` must complete both JavaScript/TypeScript and GitHub Actions security analysis. Review any newly surfaced security alerts, as scan execution by itself does not establish zero findings.
6. Verify restore, crash/reload, concurrent tab ownership, encrypted export, expired timer and PWA offline tests with only synthetic data.
7. Obtain human review, record residual-risk acceptance and ensure GitHub reports mergeability before merging.

## Repository administrator action — mandatory
The GitHub connector does not have a branch protection/ruleset write operation. Configure **Settings > Rules > Rulesets** for default branch `main`:
- Require pull request and at least one **independent** approval; dismiss stale approvals after new commits.
- Require status checks for `verify`, `browser-tests`, and each `codeql-gate` matrix result from the integrated CI workflow; choose the exact check names GitHub offers once the workflow has run.
- Require branch up to date before merge; disallow force pushes and branch deletion; restrict bypass.
- Require conversation resolution; no direct pushes, and optional signed commits per team policy.
- Ensure Pages environment has deployment branch restriction `main`; consider protection approvals based on deployment risk.
- Verify that **main ruleset enforcement is active**, not merely saved in evaluation mode.

## Production validation after merge
- Only a push to `main` with all `needs` successful may run `deploy`. A PR never deploys.
- Record merged SHA, workflow URL, `github-pages` environment URL, Pages deploy result, SBOM and asset-hash artifact.
- Test HTTPS app shell and static assets, browser privacy, synthetic bank import, encrypted export/restore in a fresh profile, active-exam hard reload, WebKit/iOS manual acceptance and offline-to-online update.
- Open browser developer tools to check console exceptions, missing assets and service worker scope.
- Do not mark release complete without physical iOS acceptance and owner security sign-off.

## Failure response and rollback
1. Stop further merges/deployments and preserve failing logs and E2E traces.
2. Identify last previously verified SHA and check whether the new code introduced IndexedDB schema changes. **Never clear/delete customer IndexedDB or Cache Storage as a rollback step.**
3. Revert the application code via an audited PR; release the revert through the same mandatory CI gates. For an urgent Pages outage, enact a documented administrator exception with audit record; do not silently bypass required tests.
4. Validate that existing bank IDs, completed attempts and active session survive rollback. Test before changing any database schema.
5. Notify users with a local-data protection notice and require an encrypted export where feasible.
6. Link incident, RCA, rollback SHA, run URLs and final owner acceptance to OPS-006 / #31.

## Limits
- IndexedDB remains unencrypted at rest and subject to browser storage eviction.
- Response-header CSP/anti-framing protections cannot be fully configured on GitHub Pages.
- CycloneDX plus asset hashes are evidence; they are **not** a signed SLSA provenance attestation.
- Branch protection configuration and actual public HTTPS site smoke tests must be verified separately.
