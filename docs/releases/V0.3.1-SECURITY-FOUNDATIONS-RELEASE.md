# v0.3.1 — Non-destructive security foundations

**Release:** GitHub Pages security engineering maintenance, not vault activation.
**Owner authorization:** Production deployment on 8 November 2026.
**Separate permissions:** Owner data migration and later plaintext deletion are NOT authorized by this release.

## Technical scope

The accumulated synthetic S1–S5 cryptographic source, authenticated recovery
and migration rehearsal from draft PRs #105, #106, #109 and #110 is added
to the repository together with a new mandatory approved production-source baseline
and compiled-artifact isolation check.

The live src/App.tsx, src/main.tsx, index.html, vite.config.ts, PWA update
policy, production Dexie v3 schema, and logical-v2 backup format remain
unchanged. The encrypted-only vault remains experimental source, is NOT
imported into the production application, and its test harness must not
appear in the GitHub Pages dist directory.

There is NO new login page, owner enrollment, encrypted-at-rest migration,
server-side authentication, new active storage schema, forced service-worker
update, stale-client revocation, site-data reset, or plaintext cleanup.
The active examprep-v1 IndexedDB remains plaintext at rest.

## Mandatory release evidence

- Reproducible npm ci, npm audit --audit-level=high, strict TypeScript,
  full Vitest, normal Vite build, approved production-source baseline and output isolation.
- Original Chromium/WebKit E2E, 32 source barrier tests, 20 actual historical
  mixed-version tests, and full S1–S5 synthetic encrypted vault, interruption,
  journal recovery and readiness tests on desktop and emulated iPhone/iPad.
- Integrated and independent CodeQL JavaScript/TypeScript and Actions, SBOM,
  asset SHA-256, protected PR merge, then a successful GitHub Pages deployment
  on the actual merged main SHA. Do not mistake passing PR tests for deployment.
- Observe and separately track existing npm audit low/moderate advisories.

## Owner physical acceptance

Without clearing the original browser site data, inspect certification
catalogs, question banks, stored attempts, and unfinished exams. Complete
an active exam before relying on backup. Export a genuine post-v0.3.0
logical-v2 encrypted backup and restore into a separate clean browser
profile; inspect all record counts and content. Physical iPhone and iPad
Safari/Home Screen PWA, import/export, offline, portrait/landscape,
background recovery and update acceptance remain outstanding under
issues #83 and #78; WebKit emulation is not physical acceptance.

## Rollback and blockers

For any regression, keep the original browser profile and IndexedDB.
Do not clear site data, forcibly downgrade Dexie, or restore an old
pre-v0.3 app. Revert code through protected PR + complete CI, preserving
compatible Dexie v3 and logical-v2 restore. Existing service-worker
controllers may continue serving a prior app shell until a safe update.

Blockers #100 old-client source writes, #83/#78 owner recovery and devices,
and #103 moderate/low transitive build dependencies remain OPEN. Both
free public Pages and later private Ubuntu VM behind HTTPS/VPN stay
supported by one portable codebase. Local vault unlock, if later enabled,
is not server-side login.

**No live data migration or future plaintext deletion is included.**
