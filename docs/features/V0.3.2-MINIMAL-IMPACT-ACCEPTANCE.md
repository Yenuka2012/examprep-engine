# v0.3.2 — Nine owner-approved low-impact features

**Status:** REVIEW-ONLY stacked implementation, no production deployment authorization. Tracks [#113](https://github.com/Yenuka2012/examprep-engine/issues/113), Phase A [#115](https://github.com/Yenuka2012/examprep-engine/pull/115), and a separate B/C development branch based on Phase A. Protected production remains v0.3.1.

## Accepted original feature numbers

| Feature | Read-only or UI-only implementation | No-regression invariant |
| --- | --- | --- |
| 1 Pre-submission summary | Existing native confirm now shows answered, unanswered and flagged counts | Cancel preserves active exam; confirmation calls unchanged durable submission |
| 2 Navigator filters | All, Answered, Unanswered, Flagged from current in-memory snapshots | No renumbering, IndexedDB writes or persisted filter state |
| 3 Timer warnings | Static accessible notices at 300s and 60s thresholds | Same `endsAt`, timer tick and expiry submission |
| 4 Bank search | Free text in title, certification, provider (when an exact catalog profile exists) and domains; certification/domain selectors | Read-only bank and catalog metadata; no new bank indexing/schema |
| 5 History filters | Certification, score bands (<60, 60–79, >=80) and ISO **UTC** completion date range | No modification to attempts; preserved sort order |
| 6 Weak domains | Lowest accuracy within categories with >=5 question observations | Small sample is not labeled a weakness; repeating a question adds observations |
| 7 Backup guidance | Expandable checklist in the bank and analytics sections | No backup, restore, deletion or recovery action invoked; unfinished exams excluded from logical-v2 |
| 10 Exam presets | 20Q/30m and 50Q/60m | Existing numeric controls and max available questions enforced |
| 12 Result breakdown | Correct, incorrect, unanswered and by-domain/revision suggestions derived from attempt question snapshots | Never recalculates/writes stored score; warns on snapshot vs stored score mismatch |

## Non-negotiable boundaries

- React UI, pure functions, and one **read-only** certification-profile lookup on opening the bank page. No new npm dependency.
- No IndexedDB schema change, encrypted-vault activation, exam lock/autosave, timeout/auto-submit behavior, scoring algorithm, PWA/service-worker update policy or backup format changes.
- Both free GitHub Pages and planned private Ubuntu HTTPS/VPN deployment remain compatible, with single-owner behavior.
- Existing v0.3.1 data stays plaintext at rest; a future encrypted cutover requires independent review/authorization (#100, #83, #78).

## Acceptance matrix before any release

- Strict TypeScript, unit tests for empty/invalid filters, score boundaries, insufficient domain samples and immutable original attempts.
- Browser E2E: question navigation and summary cancel; presets; 5m/1m timer; bank search including no results; history date reset; expanded result breakdown; active-exam backup warning.
- Chromium, desktop WebKit, emulated iPhone, source-write barrier, actual old production mixed-version PWA, isolated synthetic vault and backup restore browser matrix.
- Protected CI high-severity dependency audit, CodeQL JS/TS and Actions, independent browser E2E and source/blob freeze gate; the experimental vault must remain excluded from Pages `dist`.
- Physical iPhone/iPad acceptance and a genuine owner logical-v2 backup clean-profile restore remain distinct and cannot be inferred from emulated testing.
- Any failing test requires correction and complete same-final-SHA rerun. Do not merge stacked B/C before reconciling A. No live migration or cleanup authority.
