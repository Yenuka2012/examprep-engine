# M2.9 Phase 1 — Isolated encrypted owner UI (not yet a release)

**Status: development-only, synthetic owner browser workflow; no migration of real data.**
Source branch: M2.8 draft PR #123. Target: M2.9 #124/#125.

## Included
- Separate React entry \`encrypted-owner.html\` compiled only by \`vite.vault.config.ts\`.
- Authenticated key-check owner enrollment/unlock with distinct master and recovery secrets; synchronous React redaction on owner lock, plus owner Web Locks, background/idle lock enforced by the existing vault repository.
- Encrypted-only banks, certifications, syllabus imports; no overwrite or source DB access.
- Exam selection, navigation, answer/flag CAS autosave, explicit submission and interruption-safe completed attempts; reviewable history and read-only domain breakdown.
- Authenticated vault ciphertext export and empty-destination restore of existing encrypted vault bundle.
- Strict CSP, no network, no worker registration, localhost-only loopback guard for development. The normal GitHub Pages entry and \`dist/\` remain unchanged.

## Known limitations and required next phase
- Existing M2.7 authenticated logical-v2 *converter* draft PR #121 is NOT integrated here. It must be carefully reconciled and tested before accepting real exported source backups.
- This is a **preview/UI vertical slice**, not the complete v0.3.2 feature parity, full catalog editor, content revision workflow, adaptive learning, offline PWA or deployable encrypted-only production bundle.
- The real destination needs **separate verified HTTPS hostname** and strict origin controls. Same-origin GitHub Pages alternate paths do not isolate an old writer. Private Ubuntu HTTPS/VPN deployment remains a future host.
- No real owner source \`examprep-v1\` reads, writes, deletion, migration or rollback occurred. No production switch, no move of original browser records.
- Complete exact-head CI and expanded adversarial tests; publish only after independent recovery and physical Safari/iPad acceptance, real-backup copy/recovery, and explicit release validation.
- A local encrypted vault is **cryptographic access control**, not GitHub Pages server authentication.

## Threat controls to verify
- No import graph route from \`src/App.tsx\`/normal Pages build into \`src/vault/EncryptedOwnerApp.tsx\`.
- All content operations require verified owner binding, encrypted-only repository state and exclusive browser Web Lock.
- CRASH/LOCK at every autosave and submission checkpoint; stale nonce cannot overwrite newer answers. No pagehide data leaks through still-rendered UI.
- Real owner backups never committed, uploaded to CI, or processed on GitHub.
- Manual owner lock should remain possible even after failed autosave without accepting data loss; lock and export flows need further focused QA.
