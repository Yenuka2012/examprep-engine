# M2.9 Phase 3C — Encrypted owner offline PWA + Ubuntu HTTPS staging

**Status: synthetic build and test candidate. Nothing has been deployed to
a real owner-controlled hostname, VM or production application.** The GitHub
Pages source remains v0.3.2. This document describes the staging design,
not proof of TLS/DNS/VPN acceptance or authorization to migrate owner data.

## Origin separation and hosting

The existing source application lives at
`https://yenuka2012.github.io/examprep-engine/`. It must remain untouched.

The encrypted PWA must live at an **entirely different, owner-controlled
HTTPS origin** (host, scheme and port, not merely a path) with independent
IndexedDB, CacheStorage and Web Lock namespaces. Suggested private hostname
`exam.home.arpa` is only an illustrative placeholder. It is **not created,
reachable or automatically trusted** by this repository.

Use a dedicated Ubuntu VM, non-root static Nginx worker, server patching,
dedicated VLAN and management over a private VPN (WireGuard or equivalent),
firewall default deny, dedicated backups, and trusted TLS verification on
every owner device. A private hostname normally needs an installed, trusted
internal CA certificate or other deliberately provisioned TLS solution; do
not use public `home.arpa` certificates assumed to exist. No credentials
or owner backups belong in GitHub, Actions artifacts or web server logs.

The template `ops/nginx-owner-staging.conf` is a SAMPLE for manual review,
never activated by CI or any repository action. The VPN must be enforced in
network infrastructure; an Nginx template is not equivalent to firewall policy.
HTTP security response headers are required; HTML meta CSP alone cannot apply
`frame-ancestors` or establish DNS/TLS trust.

## Only static application shell may be cached

This staging-only build uses the already-locked vite-plugin-pwa with a custom
`injectManifest` worker `src/vault/ownerStagingSw.js`. The manifest is
limited to `owner-staging.html`, hashed `assets/*.{js,css,svg}`,
`favicon.svg` and `manifest.webmanifest`. Anything outside this
allowlist fails service-worker installation or the build artifact audit.

- **NO** runtime caching, APIs, decrypted answer banks, user JSON backups,
  credentials, tokens, IndexedDB records, session data, sync, cross-origin
  requests, or message API in the worker.
- **NO** `skipWaiting()`, `clients.claim()`, force-refresh or automatic
  takeover. A waiting worker activates only when all controlling tabs close
  naturally. Update notices guide the owner to finish an exam, verify writes
  and lock the vault first.
- IndexedDB still stores **authenticated ciphertext only** and remains
  separate from CacheStorage. Offline unlock requires a previously enrolled
  local vault, browser Crypto, Web Locks, IndexedDB and retained browser
  storage; it does not bypass the passphrase.
- Browser storage, particularly iOS Safari/PWA storage, can still be evicted.
  Regular encrypted exports and independently tested recovery are mandatory.
  Offline service worker caching is **not** an encrypted backup.
- No service-worker path or PWA staging manifest is bundled into normal
  production `dist/` or used by the existing GitHub Pages workflow.

## Build-only verification

1. On trusted developer/CI checkout, run `npm ci --no-fund`,
   `npm run typecheck` and `npm test`.
2. For a **synthetic build only**, set
   `VITE_OWNER_STAGING_ORIGIN=https://exam.home.arpa` then run
   `npm run build:owner-staging` and
   `node scripts/verify-owner-pwa-build.mjs`.
3. Inspect `dist-owner-staging/` for **only** the expected static files:
   `owner-staging.html`, `manifest.webmanifest`,
   `ownerStagingSw.js`, `favicon.svg` and hashed static `assets/`.
   Keep the build separate; never upload it through the Pages production job.
4. Do not deploy to a real machine until you own and verify its hostname,
   DNS, certificate trust, VPN, firewall, OS baseline, Nginx headers and
   backup plan. Update `VITE_OWNER_STAGING_ORIGIN` to that exact origin
   before building any deployed candidate. The runtime refuses mismatch.
5. After staging is independently verified, test physical iPhone and iPad
   Safari and installed Home Screen PWA: initial offline warmup, offline
   reopen/owner unlock, exam autosave/resume, Safari background lock,
   interrupted exam with a waiting SW, closed-tab activation, fail-closed
   lock contention, and an encrypted backup restoration into a separate
   clean origin/profile. Record exact artifacts/checks in #83 and #78.
6. Validate legacy source writer quiescence (#100) separately before any
   cross-origin real-data copy. A separate HTTPS hostname alone **does not**
   disable old source tabs on the existing GitHub Pages origin.

## Production decision

This is Phase 3C **build-only** engineering. No production merge, no
GitHub Pages deployment, no real owner data migration and no plaintext
cleanup. Remain NO-GO until real host and physical recovery evidence,
old-client quiescence, and an independent release review have all passed.
