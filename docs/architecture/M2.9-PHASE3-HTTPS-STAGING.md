# M2.9 Phase 3 — Distinct HTTPS owner staging (not deployed)

**Status:** Build-only candidate. No public GitHub Pages release, real owner data,
backend authentication, offline PWA acceptance, or cutover.

## Topology
- Production source is `https://yenuka2012.github.io/examprep-engine/`.
  It remains v0.3.2 and browser-local legacy records must not be overwritten.
- The encrypted destination must have a **different HTTPS hostname and origin**
  controlled by the owner. A separate path on the production hostname, including
  `/vault/`, **is not sufficient**.
- Build is static React/TypeScript with a dedicated entry
  `owner-staging.html` (not `index.html`), separate output
  `dist-owner-staging/` and NO service worker. Staging is not yet an offline PWA.
- A browser verifies ordinary HTTPS transport; the app checks that the
  runtime origin equals a preconfigured exact origin. This is **not** a real
  TLS, DNS control, VPN, host patch, browser support or migration attestation.
- The code also retains the pure read-only M2.6 preflight against the original
  source host and aborts React mounting before database initialization on
  a mismatched HTTP, same-origin, loopback, or unconfigured target.

## Local build (synthetic/owner-free review only)
1. Set `VITE_OWNER_STAGING_ORIGIN` to an exact owner-controlled HTTPS origin
   **without a trailing slash**, path or query, such as
   `https://exam.home.arpa` (only as a placeholder, not a real host).
2. Run `npm ci`, `npm run typecheck` and
   `VITE_OWNER_STAGING_ORIGIN=https://exam.home.arpa npm run build:owner-staging`
   in a trusted development/CI environment.
3. Verify `dist-owner-staging/owner-staging.html` exists and the original
   `dist/index.html` and Pages package are untouched. Never upload owner
   JSON backups, passphrases, transfer files, keys or exams to GitHub.
4. Do not publish this candidate on the existing GitHub Pages host. For a
   private Ubuntu staging VM, configure firewall/VLAN/VPN, operator-controlled
   DNS, HTTPS server cert and security response headers independently.
5. Web server MUST provide HTTPS/HSTS, CSP response header (including
   `frame-ancestors 'none'`), `X-Content-Type-Options: nosniff`,
   `Referrer-Policy: no-referrer`, `Permissions-Policy`, `Cache-Control`
   for stale client management, plus no cross-origin data endpoints.
6. Confirm encrypted IndexedDB, Web Locks, idle/background redaction,
   tamper rejection, independent encrypted recovery and cross-tab behavior
   on the real target. Then perform owner-specific mobile acceptance.
