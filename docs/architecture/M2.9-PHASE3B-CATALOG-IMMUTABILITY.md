## Invariants
- Certification IDs are add-only; the existing validated metadata and historical
  bank/attempt snapshots are never rewritten.
- A new syllabus **must** be a validated revision-one draft. The certification
  must exist in the unlocked vault. The logical ID is `certification/version`.
- Updates require the exact opaque ciphertext `recordId`, AES-GCM nonce and
  logical revision returned from a previous authenticated read. The candidate
  must have the same logical ID, certification, version and creation timestamp.
  Revision increments by exactly one. Times cannot move backwards.
- The storage layer authenticates the prior encrypted ciphertext outside the
  IndexedDB transaction, then compares old ciphertext + nonce and swaps inside
  one short transaction. Web Locks prevent another owner tab from accessing
  the same origin simultaneously; stale tokens fail closed. No accidental
  upsert on a missing draft. No plaintext database fallback.
- Publication consumes the exact authenticated draft token. It increments the
  revision, stamps the validated publication date and writes an immutable
  published record by the same nonce CAS. A published syllabus can **never**
  be changed or published again via the encrypted runtime; corrections require
  an entirely new version ID.
- Domain weights must sum to 100; codes/names unique; bounded objectives,
  valid source HTTPS metadata, timestamp and identifier validation are reused
  from the frozen v0.3.2 shared pure validator.
- React form state is mounted ONLY in the unlocked owner view. Owner lock,
  background lock or pagehide unmounts and redacts decrypted drafts and tokens.
