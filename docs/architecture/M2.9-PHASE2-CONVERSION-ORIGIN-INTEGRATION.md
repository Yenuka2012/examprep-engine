# M2.9 Phase 2 — Reviewed converter and origin preflight integration

**State:** DRAFT, synthetic data only. This work does not authorize a live browser migration or a production encrypted-only deployment.

## Provenance and scope

Phase 2 is based on M2.9 Phase 1 (draft PR #126), and selectively reuses the source and original tests from M2.6 draft PR #119 (distinct-origin preflight) and M2.7 draft PR #121 (authenticated offline converter). This is a focused consolidation, not an uncontrolled merge of stacked prototypes.

* `offline-converter.html`: only available from the vault-test build at the loopback preview origin `http://127.0.0.1:4174`. Converts an authenticated encrypted logical-v2 backup to ciphertext-only S3 portable vault transfer in browser memory; no owner IndexedDB or network requests. It never accepts plaintext, legacy logical-v1, invalid score snapshots, missing syllabus metadata, or unverified envelope.
* `src/vault/validatedConvertedRestore.ts`: verifies the converted transfer, every record and provenance fingerprint with **both independent credentials before any restore**. Restores only into an **empty** encrypted vault. Reads banks, attempts, certifications and syllabi through the authenticated M2.8 runtime and compares the counts to the verified manifest. Rejects an unexpected active session. On post-restore failure it locks the session and preserves ciphertext; it never deletes records.
* `src/vault/OriginTopologyPanel.tsx`: read-only candidate URL comparison, using the audited M2.6 preflight. Rejects same-origin/same-host aliases, insecure destinations, malformed URLs, passwords/query fragments and alternate loopback aliases. A syntactically separate HTTPS origin returns **TOPOLOGY_ONLY_PASS_NOT_AUTHORIZED**, never actual host/TLS approval.
* `src/vault/EncryptedOwnerApp.tsx`: adds separate converted-bundle restore to the isolated development owner UI and a read-only origin topology diagnostic.
* `e2e-vault/m2.9-converted-owner-restore.spec.ts`: browser E2E proving synthetic encrypted backup → offline conversion → verified empty-vault recovery → historical result and catalog replay → recovery unlock. Tampering is rejected without initializing owner data. No `examprep-v1` is opened.

## Hard boundaries

1. Existing production `src/App.tsx`, `src/db.ts`, PWA service worker, schema, source writer locks and frozen release build remain unchanged. The separate `vite.vault.config.ts` emits `dist-vault-test` for developer/CI use only and is excluded from `dist` and Pages deploy artifacts.
2. The offline converter has no file-upload service, backend, IndexedDB writes, persistent credential storage or service workers. Browser file processing occurs only on the local device.
3. The normal encrypted-owner UI reads/writes only the authenticated destination vault. No plaintext fallback and no automatic source data access.
4. Source backups exclude unfinished exams: complete and verify all attempts before exporting from the original production profile.
5. Same-host different-path hosting and ordinary `github.io` Pages paths DO NOT provide isolation. Separate HTTPS browser origin must later be verified for DNS/TLS/owner control and private Ubuntu VPN if selected.
6. Physical Safari/iPhone/iPad tests, real post-v0.3 logical-v2 encrypted backup independently restored, full UX parity, owner hostname acceptance, old-tab quiescence (#100), exact-head security checks, and independent recovery remain **NO-GO gates** for production encrypted-only cutover.
7. Original source browser's `examprep-v1` IndexedDB must be retained throughout. Plaintext deletion/cleanup requires a later distinct explicit authorization.
