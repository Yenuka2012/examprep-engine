# M2.1 — Static hosting portability foundation

**Status:** Candidate in draft PR. **Baseline:** v0.3.0. **Scope:** GitHub Pages (public static) and Ubuntu Server VM (private static, VPN/LAN only). **Tracking:** #85, architecture #82 / ADR-003, release acceptance #83, vault ADR-002 / PR #81.

## Builds

| Target | Command | Output | Base URL | PWA manifest scope |
| --- | --- | --- | --- | --- |
| GitHub Pages (default) | `npm run build` or `npm run build:pages` | `dist/` | `/examprep-engine/` | `/examprep-engine/` |
| Ubuntu Server VM (not automatically deployed) | `npm run build:ubuntu` | `dist-ubuntu/` | `/` | `/` |

For a clean checkout, `npm ci` first. The Ubuntu script explicitly generates the bundled JSON schema validator before Vite build. `npm run verify:hosting` checks **both** generated index files, manifests, scoped service-worker fallback, bundles and favicon paths. CI runs the Pages build, Ubuntu build and verification before uploading the existing **Pages-only** `dist/` artifact; production deploy behavior is unchanged. The second target is never published by the Pages deployment job.

## Ubuntu Level A (planned; NOT deployed)

Serve the contents of `dist-ubuntu/` from the HTTPS origin root on a stable, trusted private hostname using Caddy, accessible only via trusted LAN or WireGuard from authorized devices. Do not use `vite preview` as a production server. HTTPS is required for browser PWA/Web Crypto features. Restrict SSH, management and application access by firewall, network segmentation and VPN. Configure security response headers at the reverse proxy only after reviewing application CSP, caching and offline worker behavior. Caddy/Ubuntu service configuration, infrastructure secret distribution and server deployment are separate follow-on work; this PR does not expose any external endpoint, create VPN credentials or deploy a VM.

### Browser privacy boundary

Each browser profile and **origin** has its own IndexedDB and PWA cache; switching between GitHub Pages and Ubuntu does **not** transfer data. Use existing AES-256-GCM encrypted export/restore files after reviewing the current backup cap and recovery. **Active IndexedDB is still plaintext** until the separately reviewed encrypted-vault migration is implemented. GitHub Pages remains a public app shell, not server-side authentication. Other Pages apps under the same `yenuka2012.github.io` origin are a trust-boundary concern.

## Storage adapter seam

`src/data/repository.ts` introduces a typed read-only domain repository interface. `src/data/indexeddbReadRepository.ts` implements it against a narrowly defined Dexie-style table surface. This is the **first contract**, not the final encrypted vault adapter. Existing writes, Dexie v3 schema, live exam locks, backups, autosave, scoring and catalog behavior remain unchanged. Future refactors must preserve transactional/write coordination and perform non-destructive migrations with independently verified restore.

## Device testing

CI adds an emulated WebKit iPad project alongside existing Chromium, desktop WebKit and iPhone WebKit. The tablet project reuses synthetic bank import/exam/export smoke coverage and adds viewport/touch navigation in portrait and landscape. Emulation does not validate actual iPadOS Safari Home Screen PWA, Split View behavior, iPad file picker/export, background suspension or WebAuthn PRF; these remain **physical-device acceptance gates** under #83 and ADR-002.

## Release and rollback

- This draft PR does not merge or deploy automatically; no runtime vault encryption, new accounts, backend services, database changes or synchronization.
- Preserve `v0.3.0` Dexie schema and encrypted backup logical version 2 compatibility. Do not roll storage back to v0.2.1 or wipe browser caches/data.
- Do not merge to main without same-head CI success, independent release checks and owner authorization. iPhone/iPad physical acceptance is required before cryptographic migration and production host changes.
