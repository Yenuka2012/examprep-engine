# M2.7 — Offline authenticated logical-v2 → encrypted-vault transfer

**Status: DRAFT / PREPARATION ONLY. NO actual owner migration performed.**
Tracks [issue #120](https://github.com/Yenuka2012/examprep-engine/issues/120).
Baseline: v0.3.2 main `1256a396c3efdbfd0f9565ccf48b896eb37a2b2d`.
This is not a production-executable vault migration interface.

## Security rationale

Actual owner banks, exam histories, certification catalog and syllabi live
inside their own browser's `examprep-v1` IndexedDB. GitHub Actions and the
assistant cannot read that data. Older cached PWAs are proven able to
mutate it across an exclusive cooperative Web Lock; an IDB schema bump is
not a complete storage access-control boundary (issue #100). Therefore
pushing a fake "migration complete" state or deleting old records would be
misleading and unsafe.

The existing **full logical-v2 encrypted backup** is a practical
owner-controlled extraction boundary. Unlike the test migration journal,
it contains *only* completed exams, question banks, certifications and
syllabi; unfinished exam sessions are expressly excluded.

## Implemented test-only converter

`src/vault/offlineV2Conversion.ts` accepts an encrypted backup
object and three owner-held credentials (backup, vault master, vault
recovery) and returns a **ciphertext-only portable vault transfer**. It:

1. Rejects plaintext, unknown envelope fields, oversized files and
   unsupported logical backups.
2. Authenticates AES-256-GCM backup ciphertext and checks logical version
   **2** with all catalog arrays mandatory.
3. Validates all question banks, frozen attempts/answer keys and scores,
   certifications and syllabi; refuses any validator normalization that
   would modify metadata or drop fields.
4. Requires a non-empty inventory and independent owner master/recovery
   credentials. It creates a NEW random data encryption key, wrapped
   independently using the existing S1 AES-KW implementation with
   PBKDF2-SHA256 600,000 iterations.
5. Encrypts each validated original record under an opaque random UUID,
   retaining original source identifiers only **inside authenticated
   ciphertext**. Includes an encrypted conversion provenance journal with
   source digest, preserved record mapping and category counts.
6. Produces the existing S3 encrypted vault transfer format with an
   authenticated sorted inventory and key-check; then independently
   verifies **every restored source record** with both master and recovery
   credentials and checks the source fingerprint.
7. Returns only aggregate counts and an encrypted bundle. It does not
   open IndexedDB, write to any persistent storage, call network services,
   access service workers, change Web Locks, or trigger import/restore.

**Important:** This module is isolated under `src/vault` and is NOT
imported from the live React application. The ordinary GitHub Pages
production build must continue to exclude the vault and synthetic harness.
The transfer is a portable encrypted file **candidate**, not proof that
the production app now uses encrypted storage. The provenance journal
has its own format and must not be mistaken for the older synthetic-only
S4 journal.

## Physical owner migration sequence — NOT YET EXECUTED

- **First** complete any unfinished exam and verify the saved attempt.
- On original browser/profile, export a NEW encrypted logical-v2 full
  backup and validate a restore into a **separate clean browser profile**
  before any data movement. Retain the original browser and backups.
  No backup file, password or exam question contents belong in GitHub.
- Complete physical iPhone and iPad Safari / Home Screen PWA acceptance,
  including offline, file import/export and background recovery (#83).
- Choose a verified **separate HTTPS destination origin** (not merely a
  different GitHub Pages path); validate TLS/hostname control and
  encrypted-only app behavior, and independently prove recovery.
- Offer the converter only from a **locally trusted, reviewed, offline
  owner-side tool** after a separate release review. No current published
  owner migration interface exists. Never transmit passphrases to a server.
- Restore the encrypted transfer into an **empty destination vault only**
  with verified master/recovery secrets. Validate category counts and
  representative frozen attempt scores. Never use plaintext fallback.
- Retain original plaintext source. Observe destination integrity across
  restart and hardware/browser recovery. Treat migration as separate from
  the **later explicit plaintext cleanup decision**.

## Local test harness (synthetic data ONLY)

A dedicated offline converter page, `offline-converter.html`, is included
only in the standalone vault-test build (`vite.vault.config.ts`). Run
`npm run build:vault-test` and `npm run preview:vault-test` locally, then
open `http://127.0.0.1:4174/offline-converter.html` on the same computer.
The loopback-only UI uses a restrictive Content Security Policy with
`connect-src 'none'`; it never opens IndexedDB or registers a service
worker, and clears credential form fields after each attempt. It can
download an authenticated encrypted transfer file. GitHub Pages production
still builds only `index.html`; the production source-pinning gate and
compiled Pages artifact scan must prove this new page and its JavaScript
are NOT shipped. Automated Playwright runs use SYNTHETIC backups only.

**Do NOT use this unmerged experimental harness with real owner backups yet.**
It requires independent security/physical acceptance and a deployable
encrypted-only destination with empty-vault restore and full exam UX
before any real cutover. A transfer download alone is NOT a successful
migration or successful vault application activation.

**This PR cannot migrate live owner records. The source database is still
plaintext at rest, and no cleanup is authorized.**
