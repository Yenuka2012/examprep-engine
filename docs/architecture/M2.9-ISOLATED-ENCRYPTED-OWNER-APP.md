## What exists

A standalone browser entry `encrypted-owner.html`, with
`src/vault/ownerApp/EncryptedOwnerApp.tsx`, compiled separately by
`vite.encrypted.config.ts` to `dist-encrypted-prototype`.
It is NOT included in normal GitHub Pages Vite/PWA build. The existing
production source-fence continues to reject experimental vault files.

The React prototype supports verified owner vault enrollment, unlock,
independent recovery credential, background/pagehide/idle redaction,
authenticated ciphertext export and EMPTY-vault recovery, validated
encrypted banks/certifications/syllabi, practice exam creation, durable
CAS answer/flag/navigation writes, auto-expiry, idempotent completed
attempts, and historical attempt counts.

UI master/recovery credentials are cleared after use, not persisted in
localStorage. A single owner Web Lock excludes concurrent owner tabs.
There is **no server authentication** and no claim that GitHub Pages can
store private credentials. Original plaintext `examprep-v1` is never
imported by this prototype or its encrypted runtime.

## Strong origin gate

`ownerOriginGuard.ts` rejects the current
`yenuka2012.github.io` origin entirely, including other paths. For any
non-test usage it requires explicit and exact
`VITE_ENCRYPTED_EXPECTED_ORIGIN` set to a verified separate HTTPS
hostname. The only exemption is `http://127.0.0.1` in the explicitly
named **encrypted-test** build; the production app has no exemption.
An application-level origin check is **not** proof of actual TLS/domain
ownership, and must accompany DNS/TLS, CSP and host inspection.
