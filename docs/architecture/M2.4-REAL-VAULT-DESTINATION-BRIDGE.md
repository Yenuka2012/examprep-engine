## Implementation & trust boundary

The experimental bridge exports three explicit factory operations:
`enrollEncryptedDestination`, `unlockEncryptedDestination`, and
`restoreEncryptedDestinationIntoEmpty`. Each delegates to the real
isolated ExperimentalVaultRepository that authenticates the vault key verifier
before returning the owner session. The bridge then binds that concrete
OwnerVaultSession to EncryptedOnlyDestination, which only reads encrypted
record types and forbids automatic fallback to the old examprep-v1 DB.

The factory rejects structurally shaped fake repository objects. It is
still **not a defense against arbitrary hostile same-origin JavaScript**:
malicious script execution could manipulate application state and attack any
in-memory decrypted data. CSP, dependency integrity and XSS prevention remain
mandatory. Do not present the prototype as a real server login.

The synthetic harness at vault-harness.html uses this bridge on enrollment,
unlock and authenticated empty-profile recovery; its content read now goes
through the destination gate, not directly through the session. The authoring
API remains the owner session for synthetic encrypted writes. The harness
is a separate `vite.vault.config.ts` build on localhost:4174,
not referenced by the GitHub Pages index.html or React application entry.

## Tests and release restrictions

- Existing S1 crypto and S3 transfer Vitest are re-run against copied source;
  owner/recovery WebKit and Chromium/iPhone/iPad Playwright are mandatory.
- New browser tests use disposable localhost profiles only and deliberately
  seed a *synthetic* examprep-v1 plaintext decoy to confirm the bridge does
  not open/read/fallback to the old DB; verify owner/recovery unlock and
  decrypted-state erasure.
- CI must prove standard production dist excludes the experimental vault
  harness, secure vault DB name and test question markers.
- Additional CI job vault-bridge-browser-tests is in deploy needs, so no
  future release silently skips the gate once the bridge is integrated.
  However this PR is **draft** and intentionally does not publish anything.
- S4 journal, S5 migration readiness, actual live-source quiescence, actual
  owner logical-v2 backup/clean restore, real physical Safari/iPhone/iPad PWA
  acceptance, and both separate owner authorizations are still missing.

**NO live examprep-v1 data inspection, vault initialization, source migration,
cleanup, forced SW update, production credential use, or deployment is authorized.**
